# Model Lab Reference

> Reference page for [Model Lab](../25-model-lab.md) · Code-grounded.

It lists every `model-lab/*` route with its status codes and service, what each tab of the `modelLab` feature shows and reads, and where the stored rows are described. How the jobs, the serve worker and its GPU session work is on the parent page.

## Endpoints

The **ModelLab** route family (`model-lab/*`, `LocalApiRoutes.ModelLab`). Every route follows the conventions of [API & Hubs](../09-api-and-hubs.md#conventions). There is no Model Lab hub: a running experiment's progress rides `TrainingRunHub` under the experiment's id ([hub reference](09-signalr-hubs.md#hub-inventory)).

- `model-lab/checkpoint-preflight` (POST: can this Hugging Face checkpoint be traced on this card and paired with this installed GGUF, answered before any weight is transferred; with `baseArtifactId` instead of a repository, the same check on a checkpoint already on disk, with no network; it also names the default steering layer and each block's kind by the family's rule (an OLMoE block is always full attention), the config's `modelType`, `attentionSupported` with the reason in `attentionRefusalMessage` when a trace of it cannot record attention, and `traceRefusalMessage` when it cannot be traced but can still be steered (a config with `output_router_logits` set); a refusal is a 200 with a stable code: `UnsupportedModelType` for a family Model Lab has not traced (Qwen3.5 and OLMoE are), `ArchitectureMismatch` when the checkpoint's family has another GGUF architecture than the installed GGUF (`qwen35` for Qwen3.5, `olmoe` for OLMoE), whatever the widths). Operator policy. Service: `ModelLabCheckpointPreflightService`.
- `model-lab/checkpoint-download` (POST: the preflight, then the license gate, then the base-checkpoint download, all under one 200 that carries any refusal)
- `model-lab/experiments` (GET: the saved experiments, the running one and whether this platform can trace; POST: start a trace, or with `steering` a derive and three arms, 202, or a 409 with a stable `reason`; `recordAttention` (trace only, a 400 with `steering`) also records each generated step's attention row at up to eight full-attention blocks the node picks (`ModelLabTraceSpec.AttentionLayersFor`), refused with the 409 `AttentionUnavailable` when the checkpoint's family has no attention capture (Qwen3.5 and OLMoE have one), an OLMoE config states anything but full attention at every block (`layer_types`, `sliding_window`, `attention_chunk_size`, `num_kv_shared_layers`), or the config does not give its block kinds and heads or has no full-attention block; a steering row's arms are in its `result`, and its vector has no route out), `model-lab/experiments/{experimentId}` (GET, DELETE; a trace's `result.tokens` carry the top 20 raw and processed candidates per step when the trace recorded them), `.../cancel` (POST), `.../trace` (GET: a trace row's measured records, decrypted and hash-checked), `.../attention/{layer}` (GET: one captured block's attention rows of a trace started with `recordAttention`, decrypted and hash-checked; 200 `{ layer, heads, kvHeads, topKeys, rows[{ step, queryPosition, heads[{ keys[], weights[], rest }] }], truncated, droppedRecords }` with the weights as fractions, 404 for a run that recorded none, a block it did not capture or a steering row, 422 when the stored rows do not read back. Service: `ModelLabExperimentReader.ReadAttentionAsync`), `.../lens` (GET: the logit lens a contract-5 trace records for every block of a checkpoint with 2 to 64 blocks, read from the same hash-checked trace blob; 200 `{ layers, topTokens, tiedEmbeddings, vocabSize, steps[{ step, blocks[{ layer, ids[], logprobs[], chosenLogprob, chosenRank, entropy }] }], texts[{ id, text }], truncated, droppedSteps }` with the entropy in nats and each text once; the lens has its own cap and footer, so `truncated` here and on `.../trace` are independent. A derived analysis: the model's final norm and output layer applied to each block's output. 404 for a run saved before contract 5, a checkpoint outside 2 to 64 blocks, a run the script skipped the lens for or a steering row, 422 when the lens lines fail their check (steps 0, 1, 2, ... matching the summary, the lens footer and the token count; summary blocks 0 to B−1 and its truncated flag equal to the footer's; per block the top-token count, a rank of at least 1 that is null exactly where the chosen logprob is, an entropy that is null or not negative, a text for every id). Service: `ModelLabExperimentReader.ReadLensAsync`), `.../routing` (GET: the experts a contract-8 trace recorded for every mixture-of-experts block at each step, read from the same hash-checked trace blob; 200 `{ layers, experts, expertsPerToken, normalizedTopK, steps[{ step, blocks[{ layer, experts[], weights[] }] }], truncated, droppedSteps }` with each block's top-k expert ids in the router's order and the exact bf16 weights the experts received; the routing has its own cap and footer. A measurement: step `s` is the router output at the position whose logits chose token `s`. 404 for a run saved before contract 8, a checkpoint without a router (a dense Qwen3.5) or a steering row, 422 when the routing lines fail their check (steps 0, 1, 2, ... matching the summary, footer and token count; every block with exactly k distinct ids inside the expert count and k weight bit patterns in [0, 1]). Service: `ModelLabExperimentReader.ReadRoutingAsync`), `.../notes` (PUT `{ notes }`: the operator's note, at most 8,000 characters, blank clears; 204, 404, or the 409 `Busy` while Running) and `.../pin` (PUT `{ pinned }`: a pinned run is never trimmed; 204, 404, 409 `Busy` or `PinLimitReached` past 20 pins); list rows carry `isPinned` and `appVersion`, the single read also `notes`
- `model-lab/prompt-tokens` (POST `{ modelName, systemPrompt?, prompt, disableThinking }`, the inputs of a finished Next token run: the llama-server already running that model renders them with its chat template, thinking off only when `disableThinking`, and tokenizes the result; 200 `{ renderedPrompt, tokens[{ id, piece, special }], tokenCount, truncated }` with the list capped and `tokenCount` the full count; `special` is true only for a token llama.cpp parses as a control token, so a thinking tag can be an ordinary token; each distinct token is checked on its own, so a long prompt takes a moment. 400 on validation, and the 409 `ModelNotLoaded` when no llama-server runs the model or its server went away mid-call: it never loads one. Service: `IModelLabPromptTokensService`)
- `model-lab/architecture/{modelName}` (GET: an installed GGUF's blocks, block kinds and tensors grouped by component, from the header alone; `detailed` for an architecture with a registered descriptor (`qwen35`; `qwen35moe`, whose HF names assume a checkpoint that stores each block's experts fused, so a stored `ffn_gate_exps`/`ffn_up_exps` row is `sliced`, one half of `mlp.experts.gate_up_proj`; `llama`, whose HF names assume the standard `LlamaForCausalLM` conversion; `olmoe`, whose HF names are the transformers in-memory ones, so its separately stored `ffn_gate_exps`/`ffn_up_exps` are `sliced` halves of `mlp.experts.gate_up_proj`; in every detailed family a block kind whose blocks store Q/K/V fused in `attn_qkv`, separately, or both gets template labels for that layout (`ModelLabQkvLabels`), linear blocks never counted) with HF tensor names and an operation template per block kind inferred from llama.cpp at the pinned tag (none for a mixture-of-experts `llama` file), `overview` for any other architecture, `unreadable` with the read failure; an unknown model is 404; `suggestedBaseRepo` is the `owner/name` of the header's `general.source.repo_url`, else `general.base_model.0.repo_url`, when that URL is exactly `https://huggingface.co/owner/name`; `hyperparameters` holds the values the header declares (file type, `general.parameter_count` never the tensor sum, block, MTP and split counts, head counts and head sizes, width, context, experts and experts per token, full-attention interval), each null when absent or outside 0 to 2^53-1, and is null for an unreadable file. Builder: `ModelLabArchitectureBuilder`, descriptors: `ModelLabQwen35Architecture`, `ModelLabLlamaArchitecture`)
- `model-lab/architecture/{modelName}/pytorch` (POST with `source: checkpoint` and `baseArtifactId`, or `source: huggingface` and `repoId`/`revision` (only `config.json` is fetched): the model's PyTorch module tree and per-block op graphs from a source job, or from the cache keyed by the config's hash and the installed transformers and torch versions, joined to the GGUF descriptor; 200, 404 for an unknown model, 409 with a stable `reason` (`RemoteCode`, `UnsupportedModelType`, `RuntimeUnavailable`, `Busy`, ...); GET: the last index built for that model on the installed runtime, else 404)
- `model-lab/pytorch-source` (GET `?index=&file=`: one file the index lists, read from the active runtime's transformers or torch package after a containment and sha256 check, else a 409 such as `SourceNotInIndex` or `SourceChanged`). Service: `ModelLabPyTorchSourceService`, join: `ModelLabPyTorchJoiner`
- `model-lab/playground/runs` (GET: the saved training-stepper runs, newest first, with `platformSupported`, `unsupportedMessage` and `maxRetainedRuns`; POST with every knob required (`dataset` `xor` or `spirals`, `learningRate` 0.0001 to 10, `residual`, `sharedBlock`, `depth` 1 to 4, `hidden` 2 to 16, `steps` 1 to 2000, `seed` 0 to 2147483647, each bound published in the OpenAPI document): trains one tiny network on the CPU inside the request and answers 200 with the saved run (`config`, `outcome {kind, atStep, updatesApplied}`, `finalLoss`, `finalAccuracy`, `traceByteCount`), a 400 on validation, or a 409 `ModelLabPlaygroundBlockedResponse {reason, message}` with `UnsupportedPlatform`, `RuntimeUnavailable`, `Busy` or `RunFailed`, which saved nothing; a diverged run is a 200 whose `outcome.kind` is `diverged`), `model-lab/playground/runs/{runId}` (GET: the run plus its recorded trace as JSON, 404, or the 409 `TraceUnavailable` when the trace blob is missing or fails its integrity check, the row still deletable; DELETE: 204 once the row and its trace scope are gone, 404). Operator policy, no agent or MCP tool reaches them, no hub event. Service: `ModelLabPlaygroundService`
- `model-lab/warm/eject` (POST, body-less: ends an Idle warm worker; 204, also when nothing is warm, the 409 `Busy` while a job holds it, or the 409 `OrphanWorker` when its exit was not seen. Source: `IModelLabWarmResidentSource`)

## The `modelLab` feature folder

**Model Lab** at `/model-lab` (Models nav group, Advanced only). It opens on the Architecture tab; one page model picker above the tabs lists every installed llama.cpp GGUF and drives Architecture, Next token and Inspect, while Same-prompt A/B and Trace keep their own model fields.

### Same-prompt A/B and Inspect

Same-prompt A/B: one prompt and one seed, drawn when none was typed, against two installed llama.cpp models, one after the other over the chat hub's `StreamDirectInference`, with outputs, token counts and timings side by side. Nothing is saved and there is no endpoint of its own. The page states that identical settings do not guarantee identical results and that a difference alone is not evidence of a meaningful effect. Stop cancels the active run and the next never starts; a failed run does not stop the next. The Inspect tab opens the Models dialog's `ModelInspectPanel`, shared from `core/models/inspect/`, for the page's model, read only once the Inspect tab has shown that model, with no data of its own.

### Trace

Trace: pick a checkpoint and a GGUF, check them, confirm the license, download, then run one trace at a time with live progress over the run hub, Cancel, and a read-only view of saved traces, labelled as measured only when the trace can be read. In a saved trace each token is a keyboard-reachable button, quoted with its whitespace escaped and named "Step N", when the trace recorded candidates, and a step past the trace byte cap keeps its row with empty norm cells; the selected step opens `NextTokenStepView` with its exact PyTorch candidates (`toStepEntry` in `models/ModelLabTrace.ts`), raw logits by default and processed scores behind a `SegmentedControl`, saying so when the two are identical, with the basis as the title of the step view's `trace` prop; with it set, the step view marks the chosen candidate by token id rather than text, words its missing-choice (neutral on the processed list), no-candidates and simulation notes for the trace and drops the llama-server defaults note. An older trace says it recorded no candidates. A saved trace switches between Table and Step through (`TraceStepper`): a step slider with previous and next buttons, the generated tokens with the current one marked (`aria-current`), a strip of every block from the result's `layerKinds` (older traces: the traced blocks) shaded by that step's residual norm, and the step's candidates (`TraceStepCandidates`, shared with the table). It imports nothing from Next token or the chat hub, which a test checks. Selecting a full-attention block the run recorded opens `TraceAttentionPanel`: `getModelLabExperimentAttention` per block, only while it is selected; a head picker naming each head's key/value head; the current row's stored keys as a table with one neighbour token each side and the rest of the row (the accessible view); and an `aria-hidden` `MatrixChart` from `@mantine/charts` of every step's row, at most 256 columns, whose cell states (weight, floored, not in the top K, later position, row not kept) each have a legend entry. It is badged `derived` ("Derived"), with the note that the weights are recomputed in float32 beside the kernel, top K kept and floored, and the block's query and key/value head counts; the head picker carries the `structural` badge ("Read from the file"). Attention is recorded for Qwen3.5 and OLMoE; the explanation texts state both families' facts (Qwen3.5's per-head norm, partial RoPE and output gate; OLMoE's norm over the whole projection, `clip_qkv` clamp, RoPE on the full head and one query head per key/value head). A linear block, an unrecorded block and an older trace show the `unavailable` basis ("Not available") with an explanation. Under the candidates, `TraceLensPanel` shows the trace's logit lens (`getModelLabExperimentLens`, fetched once per run while the stepper is open): a table with one row per block (kind, the lens top token, the chosen token's lens probability as a bar with the number and rank beside it, and the spread in nats to two decimals), the selected block's top tokens (`CandidateBar`, exported from `NextTokenStepView`) with "tied for first" when the chosen token shares rank 1, and the last block's lens value beside the raw output value with the 1e-4 nats tolerance stated. It is badged with the `derived` basis ("Derived") and adds no tab stops; the block strip selects the row. A run without a lens shows the `unavailable` basis. Below it, `TraceRoutingPanel` shows the routing used to predict the current token (`getModelLabExperimentRouting`, fetched once per run and only when `result.routing` exists), badged `measuredTrace` ("Measured in the trace") once the routing was read, with the note that the GGUF in llama.cpp may route differently: a table with one row per mixture-of-experts block (kind, the chosen experts as chips "E12 0.31" ordered by weight, rounded for display only and never ellipsized, and the sum of the weights, left out when the checkpoint renormalizes them to 1), the selected block's weights as bars, and that block's most picked experts over the run with the step count (`models/ModelLabRouting.ts`, badged derived; a truncated run counts its saved steps). It adds no tab stops; the block strip selects the row. A dense or older run, or a steering run, shows the `unavailable` basis with why. The trace form has a Record attention switch, off by default and disabled with the preflight's `attentionRefusalMessage` (or the generic reason) unless the check reports `attentionSupported` and a full-attention block; a checkpoint the preflight says cannot be traced (`traceRefusalMessage`) shows that reason and the trace start stays disabled, while steering stays offered. `TraceLayerPicker` lets a trace name its blocks; none chosen sends no `layers` and the server traces its quarter points.

### Architecture

The Architecture tab (`ArchitectureExplorer`) reads `getModelLabArchitecture` for the page's model and shows it as a hierarchy derived in `models/ModelLabHierarchy.ts` from what the file holds: a row of Embedding → Blocks ("n in this file") → Output, with MTP and Other beside it, each only when present (groups outside the blocks by `componentId`; Other is everything but `embedding`, `output_norm` and `output`); under Blocks the trunk as chips in index order, where a contiguous segment that repeats a unit of two or more same-kind runs at least twice gets one chip per repetition ("0–3 · 3 linear + 1 full") and otherwise one per run ("0–15 · Full attention ×16"), a one-block chip being the block button itself; an index the file lacks shows a "blocks not in this file" marker (an MTP block between trunk blocks is a boundary, not a gap). Only the chip holding the selection shows its 28 px block buttons; every row entry is one button with `aria-pressed`. A traced block carries a dot and a block named in the laid-over run's saved routing steps a square (the run's routing query, read once in the explorer only for a family with a `router` node; a run that recorded none says so instead of showing zero), and a chip counts both ("2 traced · 3 routed"). Below the row a breadcrumb of plain buttons (Model › Blocks › chip › Block; Model › MTP › Block; last item `aria-current`) leads up, and the detail matches the selection: the whole model (header values, outside groups, counts, a split-file notice), Blocks (counts per kind, the repeating pattern only for a complete unsplit `detailed` trunk with embedding and output, attention and expert values, the chips as buttons), a chip (kinds, span, traced and routed blocks, whether blocks of one kind hold the same tensors and stored types, each contained kind's operations as text inferred from llama.cpp, no graph or tensor actions, "Open block N"), MTP (its blocks and the separate-path note), Embedding, Output, Other, or a block. A detail control or breadcrumb item moves focus to the new detail's heading (a row pick does not). A "Show graph" switch above the row (off by default, local state) draws `ArchitectureModelGraph`: the row's entries at chip level as a read-only React Flow canvas, two nodes per row in reading order, whose height grows with the rows so the first fit keeps every node in view at zoom 0.75 or more down to a 360 px screen (no drag pan or wheel zoom, so the page scrolls over it), with the row's traced and routed labels and inert `aria-hidden` gap markers. It draws edges Embedding → chips → Output only for a complete trunk (`trunkComplete`) with a trunk template, badged inferred from llama.cpp citing that template's source; otherwise the groups stand in index order. Blocks, MTP and Other are never connected. A node click selects as the row does, the row stays the keyboard path, and past 60 groups a note replaces the canvas. Each Model Lab canvas (model, template, PyTorch graph) has its own React Flow `id`. The header values (`hyperparameters`) appear in `ArchitectureValues`, each with a `FieldInfo` text under `pages.modelLab.architecture.values` and its basis (`structural`, or `derived` for counts and the vocabulary from a rank-2 `token_embd.weight`); a null value is not shown, a zero is, and experts only when `expertCount > 0`. Each block's tensor groups are badged as read from the file, and for an architecture the server describes in detail (`qwen35`, `qwen35moe`, `llama`, `olmoe`) the block kind's operation template as a read-only React Flow graph badged as inferred from llama.cpp (Q/K/V labels follow the file's separate, fused or mixed storage); a link or jump to a block the file lacks shows `pages.modelLab.architecture.blockMissing` (an Embedding, Output, Other, Blocks or MTP it lacks, `outsideMissing`; a range that is not one chip, `hierarchy.rangeMissing`, never a guessed chip) instead of a detail; a saved trace of the same installed model is laid over its blocks by block index, and only once the loaded experiment list holds it as a finished trace of that model, so a linked id never fetches a foreign or unconfirmed trace. When the file's graph has a `router` node, the selected block's detail also shows that block's most-picked experts over the laid-over run (as many as it picks per token) and how often (`ArchitectureBlockRouting`, derived, from the run's routing query that the stepper shares; nothing for a run without routing; a run gone from the refreshed experiment list stops being laid over); the stepper's routing panel has the reverse jump to the selected block. An `overview` architecture gets groups only, never an invented graph. A `detailed` file with no template (a mixture-of-experts `llama`, say) says why no graph is drawn, and an architecture whose Hugging Face names assume one source layout shows its `pages.modelLab.architecture.layoutNote.<architecture>` notice (`llama`, `qwen35moe` and `olmoe`, whose module paths wrap anywhere on a narrow screen). A tensor row's value relation is a label: `sliced` marks one half (gate or up rows) of a fused Hugging Face tensor such as `qwen35moe`'s `mlp.experts.gate_up_proj`, kept like `reordered` whatever the stored type.

An Overview / Detail / Math switch (`ArchitectureExplanation`) explains the selected block, tensor group, every operation of the template (an accordion that is the keyboard path; a click on any graph node opens its item) and the trace values. The text lives under `pages.modelLab.explain` in the Model Lab locale bundles; an operation node takes the first text at the chosen level from `opByKind.<kind>.<id>`, then `arch.<architecture>.op.<id>`, then the shared `op.<id>` (`operationCandidates`); `qwen35moe` reads its own `arch.qwen35moe` texts (the renormalized top-k weights, a residual that adds the mixture-of-experts output) before the `qwen35` ones (`architectureFallbacks`), so every `arch.qwen35` text must hold for both; `olmoe` has no fallback and overrides every shared text that states a Qwen or llama fact (whole-projection Q/K norms, NEOX RoPE, top-k weights used as is, per-expert storage), and the mixture-of-experts operations (router, top k, routed and shared experts) have shared texts. So the shared text describes a plain pre-norm transformer, a family's own facts sit under its `arch` key, and a kind text must hold for every family with that kind. `ModelLabQwen35Explanations.test.ts` pins every qwen35 node's text at every level to a file snapshot. The text is rendered with `ChatMarkdown` (so its math loads the lazy math chunk), and is badged by basis: inferred from llama.cpp, or `interpreted` ("Explanation, not measured"); the block's trace summary is badged `derived`. Every Model Lab evidence badge is a `BasisBadge` (`ExplanationBasis`: `measuredLlamaCpp`, `measuredTrace`, `derived`, `structural`, `{ inferredFrom }`, `simulated`, `interpreted`, `unavailable`). `ModelLabExplanation.test.ts` fails when a template node id, component, block kind or trace value lacks text in either language.

### Saved runs: pin, compare, notes and steering

Each saved row has a Pin toggle (aria-pressed; the retention line counts pinned of `maxPinnedExperiments`) and a selection checkbox; Compare opens `SavedExperimentComparison` for 2 to 4 finished runs of one kind (otherwise disabled with the reason). It lists every fact that differs above a facts table (`compareFacts` in `models/ModelLabComparison.ts`: checkpoint, revision, installed model, device, torch, transformers, CUDA, app version, seed, the trace's blocks and token limit or the steering block, scale, arm builds, vector length and contrast prompts), saying a difference may come from those facts rather than the experiment, and marks facts an older run did not record as not checked; then each run's output, a per-step token table with the first difference marked, each run's candidates for a chosen step, the mean norm per block every run traced, or each steering arm's outputs side by side, and each run's note read-only. A single saved run has a note editor (8,000 characters, Save and Clear). A steering run starts from an editable starter set; `SteeringExperimentResult` shows its arms side by side with the limits of the comparison, and a failed run keeps what finished.

### Next token

The Next token tab (`NextTokenExplorer`) runs one prompt on the page's model, when it is a llama.cpp chat model (otherwise Run stays disabled with the reason), over the same `StreamDirectInference` with `topLogprobs: 20`, offers the same Thinking off switch for a reasoning-capable model, and lists the kept logprob entries as keyboard-reachable step buttons, answer steps by default and thinking steps behind a switch, with the left-out counts. `NextTokenStepView` shows a step's candidates as `Progress` bars badged `measuredLlamaCpp` (`measuredTrace` for a trace step; no `@mantine/charts` there; only the attention map uses its `MatrixChart`), the chosen entry marked or said to be missing, and the rest of the vocabulary, badged `derived`; beside them `simulateSampling` (`models/NextTokenSampling.ts`) re-weights only the shown candidates with top-k, top-p, min-p and temperature in llama.cpp's default chain order, always badged `simulated` and labelled as a simulation that leaves penalties out and states llama-server's defaults. A run that completed, or was stopped after some output, then calls `tokenizeModelLabPrompt` once with the inputs it sent (a mutation, never a query, so no render refetches it); `NextTokenPromptTokens` shows the rendered prompt's tokens as chips between the form and the results, badged `measuredLlamaCpp` once they arrived, with a reading line while the request is out, whitespace drawn, llama.cpp control tokens (`special`) dashed and named as control tokens, never as "role markers" or "thinking tags", piece and id as each chip's accessible name and in a readout on hover or focus, one Tab stop, on the first chip until focus moves, then where focus left; the arrow keys between them, the count, a truncated note, and for the 409 `ModelNotLoaded` (model unloaded or its server gone) a line to run again.

### The URL and cross-tab jumps

The URL holds the investigation context: `tab`, `model`, `block`, `trace`, `experiment`, `run` and `level` (`modelLabSearchSchema` in `models/ModelLabNavigation.ts`; an invalid field is dropped alone, defaults are stored as absent). `block` is a block index, `embedding`, `output`, `other`, `stack`, `mtp` or a chip's range token `first-last` (no leading zeros, first < last ≤ 2,147,483,647); absent is the whole model. While Architecture is hidden, its model, block and trace stay as last shown, so a hidden tab mounts no detail and reads no run. `features/modelLab/pages/ModelLabRoutePage.tsx` is the route adapter; `ModelLabPage` takes the search and a change callback, or keeps its own search when rendered without a route. Every change goes through `applyModelLabPatch`, which drops the block and trace when another model is chosen before applying the patch; a jump between tabs pushes one history entry, every other change replaces it, and none moves the scroll position (only a tab switch or a jump brings a stuck tab bar back to the top; a jump moves focus to the target's tab). A model in the URL counts once the held model list has it; otherwise the page says it is not installed. A saved experiment opens only once the loaded list holds its id. The Next token prompt is not in the URL: a numbered intent reaches Next token only while its tab is shown and is applied once, for its own model, during render, so a blocked jump or a later edit wins; a reload of that link drops the prompt. Next token resets Thinking off and its trace note when the page's model changes, and names the model a shown result came from when it is not the chosen one. A traced layer's column in a saved trace opens that block in Architecture with the trace laid over it; Open trace in Architecture opens the overlaid trace; Try in Next token prefills the paired GGUF, the prompt and Thinking off, with a line that llama.cpp on the GGUF can tokenize and score the prompt differently from the checkpoint trace. Next token's explanations reuse `ArchitectureExplanation` under `pages.modelLab.nextToken.explain`, badged `interpreted`, and `ModelLabExplanation.test.ts` fails when a topic lacks text in either language. Nothing is saved.

### Locale bundles

The page suspends on `loadModelLabStrings`, because `pages.modelLab.*` lives in `features/modelLab/locales/`, chunks named so the lazy budget counts them.

### Training stepper

The Training stepper tab (`playground`, last; `PlaygroundPanel`) needs no GGUF and ignores the page model picker: `PlaygroundRunForm` sets the eight knobs (dataset, learning rate, residual, shared block, depth, hidden size, steps, seed), each with a `FieldInfo` card, validated by the generated request zod; a run trains on the server's CPU inside the request and is saved; the saved-run list (read only once the tab has shown) opens a run by `run` in the URL, only once the list holds it, and deletes it. `PlaygroundStepper` replays the recorded steps phase by phase (forward, loss, backward, update) under a line saying the values are recorded playback and the network is not run again; each value carries `measuredTrace`, the update and visit-sum checks (`models/ModelLabPlayground.ts`) `derived`, the phase text `interpreted`, and a phase that did not run after a non-finite loss or gradient `unavailable`. A shared block shows each visit separately on its one parameter set. Other platforms see why it is Linux only.

## Stored rows

`ModelLabExperiment` and `ModelLabPlaygroundRun` and their file blobs (a trace's records and attention rows, a steering run's vector, a training-stepper run's `trace.json`): encrypted columns, AAD and tables in [Data & Persistence](../08-data-and-persistence.md#entity-inventory).
