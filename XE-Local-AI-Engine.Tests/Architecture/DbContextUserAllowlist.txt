#   permanent - composition, migration bootstrap, or a documented maintenance job. It stays.

# ---------------------------------------------------------------- permanent: chat persistence
# Operator decision 2026-09-21. NodeChatPersistenceWriter already IS the store seam: it owns the scope that
# resolves the context and the conversation-scoped write lock every other holder routes through, and that lock
# hierarchy is documented architecture (docs/wiki/05-chat.md, "The persistence lock hierarchy") rather than an
# accident of where the code landed. Moving the SQL into Client.Persistence would drag the chat domain
# vocabulary down with it — the SQL binds NodeChatMessageStatusValues members as parameters and takes
# NodeChatMessageCorrelation in every correlated write — for an import change in roughly a hundred files that
# relocates no persistence concern. Measured in Plans/csharp-baseline-2026-09-17/progress/S7c-analysis.md.
#
# Permanent covers these eight types, by name. A NEW Services/Chat type that takes a context is unlisted and
# fails the fence, which is the half of this decision that has to keep biting.
XE_Local_AI_Engine.Client.Services.Chat.NodeChatPersistenceWriter|permanent|Owns the conversation-scoped write lock and the scope that resolves the context; the seam the other seven Chat holders route through.
XE_Local_AI_Engine.Client.Services.Chat.Implementation.NodeChatConversationCommands|permanent|Raw-ADO conversation commands plus the bulk purge-cancel transaction, inside the writer's callback.
XE_Local_AI_Engine.Client.Services.Chat.Implementation.NodeChatFeedbackStore|permanent|Reads and writes message_feedback through the writer's callback.
XE_Local_AI_Engine.Client.Services.Chat.Implementation.NodeChatMessageCommands|permanent|Raw-ADO message commands and the run-envelope writes; its terminalize transaction is opened only for a terminal status.
XE_Local_AI_Engine.Client.Services.Chat.Implementation.NodeChatPersistenceSql|permanent|The shared raw-ADO read and probe queries every Chat collaborator reuses, as pure functions over a caller-supplied context.
XE_Local_AI_Engine.Client.Services.Chat.Implementation.NodeChatReadModel|permanent|Conversation and message reads through the writer's callback.
XE_Local_AI_Engine.Client.Services.Chat.Implementation.NodeChatRestartRecoveryService|permanent|Recovers rows left mid-turn by a crash, in one transaction on the shared Guid.Empty gate.
XE_Local_AI_Engine.Client.Services.Chat.Implementation.NodeChatVariantBranchService|permanent|Branch-copy and variant minting, two transactions plus the context's own content-encryption helpers, which bind the at-rest AAD per row.

# ---------------------------------------------------------------- permanent: knowledge persistence
# Operator decision, 2026-09-21: the knowledge retrieval and ingestion lane stays in the application layer, on three
# measured grounds. (1) KnowledgeDocumentStatus is bound as a SQL parameter by six of these types AND is a shipped
# OpenAPI schema id and a SignalR parameter, so moving the SQL renames a generated client symbol. (2) Two units of
# work hold application logic open inside one transaction: KnowledgeDocumentCatalogService.ResetStaleDocumentsToPendingAsync
# evaluates the embedding-model staleness policy between its SELECT and its UPDATEs, and
# KnowledgeDocumentBlobStore.UpdateRepositoryDocumentAsync keeps the transaction open across an encrypted blob write
# and its atomic rename, rolling both back together. (3) Four of these interfaces are injected by host endpoints, which
# EndpointDependencyTests forbids for a Persistence type. Entries are per type: a new knowledge holder fails as unlisted.
XE_Local_AI_Engine.Client.Services.Knowledge.ContextExpansionService|permanent|Expands a chunk hit into its neighbours over the raw connection, merging disjoint windows into one parameterized query per document.
XE_Local_AI_Engine.Client.Services.Knowledge.FtsSearch|permanent|The chunk_fts MATCH query; FTS5 is not expressible in LINQ, so it stays raw ADO wherever it lands.
XE_Local_AI_Engine.Client.Services.Knowledge.KnowledgeChunkEmbeddingReuseStore|permanent|Embedding-reuse cache lookup; its batched IN-list binds KnowledgeDocumentStatus.Indexed, a shipped contract type.
XE_Local_AI_Engine.Client.Services.Knowledge.KnowledgeDocumentBlobStore|permanent|Encrypted document-blob storage whose repository-update transaction stays open across the blob write and atomic rename, and encrypts through an application-layer protector.
XE_Local_AI_Engine.Client.Services.Knowledge.KnowledgeDocumentCatalogService|permanent|Document reads and reindex resets; its stale-reset transaction evaluates the embedding-model policy between the SELECT and the UPDATEs, and host endpoints inject its interface.
XE_Local_AI_Engine.Client.Services.Knowledge.KnowledgeDocumentPurgeService|permanent|Ordered child-to-parent purge in one transaction, with the on-disk delete strictly after commit; a host endpoint injects its interface.
XE_Local_AI_Engine.Client.Services.Knowledge.KnowledgeIndexWriter|permanent|Writes sections, chunks and vectors in one transaction against a captured content-hash revision, binding KnowledgeDocumentStatus twice.
XE_Local_AI_Engine.Client.Services.Knowledge.KnowledgeIngestionService|permanent|The ingestion state machine: its reads and status writes interleave with the extractor, chunker, embedder and notifier the persistence layer cannot reference.
XE_Local_AI_Engine.Client.Services.Knowledge.KnowledgeSearchService|permanent|Hybrid retrieval: fusion, rerank budget and hydration around the chunk reads, driven by provider-layer collaborators; a host endpoint injects its interface.
XE_Local_AI_Engine.Client.Services.Knowledge.ManagedCosineVectorSearch|permanent|Cosine-similarity scan over the packed-float vector column, allocation-free over a pooled buffer and recording application-layer retrieval metrics.
